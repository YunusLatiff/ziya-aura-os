# Aura OS v0.8.6

## Dual-port architecture
- Aura Operations Dashboard: `http://localhost:4310`
- Ziya CRM: `http://localhost:4311`
- Aura remains the backend authority and sole CRM writer; the CRM UI proxies API calls to Aura. This avoids two Node processes concurrently writing `data/crm.json`.
- The production watchdog independently checks both ports and restarts either UI/service if required.

## Monthly approved-lead quota
Defaults:
- Global approved lead cap: 180/month
- Vision: 60/month
- Peter: 60/month
- MJ: 60/month
- Timezone: Africa/Johannesburg

Only Friday `APPROVED` leads consume quota. Rejected, rework and duplicate candidates do not consume approved-lead quota. Final monthly batches automatically shrink to the number of approval slots still available. If an approval reaches the cap during review, it is preserved as `QUOTA_HELD` rather than discarded.

The quota resets automatically because counting is calendar-month based in the configured timezone; historic statistics remain in the underlying data.

## Tavily guard
Defaults:
- Hard Aura stop: 900 Tavily credits/month
- Existing percentage stop: 90%
- Reserve: 25 credits

Tavily calls are blocked when the hard 900-credit cap is reached, regardless of remaining provider allowance.

## API key security
The Tavily key is persistent in `.env`, not embedded in source files or the distributable ZIP. Run `configure-tavily-key.ps1` once to save the new key locally with hidden terminal input. This prevents the key from being copied into source-control history, patch ZIPs and code backups.

## Tony
Tony remains protected and unchanged. v0.8.6 does not add CRM access to Tony or modify Tony's source/configuration/workflow.
